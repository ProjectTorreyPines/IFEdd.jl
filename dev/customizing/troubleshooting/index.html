Troubleshooting

The generator reports every failure as IFEdd.GeneratorError, carrying a reason::Symbol and a detail string. Catching by reason is stable API; the detail text is for humans.

try
    IFEdd.generate_user_dd(; …)
catch e
    e isa IFEdd.GeneratorError && e.reason === :bad_supertype && …
end

Schema errors

ReasonCauseFix
:schema_dir_missingschema_extra_dir does not existCheck the path
:subdir_in_schema_dirThe schema directory contains a subdirectoryFlatten it — one JSON file per IDS, no nesting
:malformed_jsonA file under the schema directory will not parseJSON.parsefile it locally to find the bad line
:bad_supertype_supertype names an abstract outside the latticeUse a name from the lattice
:bad_marker_placement_supertype on a leaf scalar or on timeMarkers belong on STRUCTURE / STRUCT_ARRAY only
:user_name_shadows_ifedd_defaultConcrete named summary, build or driverPick a distinct name

Runtime warnings

@warn "… was generated against IFEdd abstracts.json with sha256 …" at load time means IFEdd was upgraded since your container was baked. Rebuild and restart:

using Pkg; Pkg.build("MyPkg")

The warning fires once per session and is deliberately not an error, so a partially upgraded environment still loads.

MethodError: no method matching f(::MyPkg.dd, …) means the callee constrains its argument to a concrete type — ::IFEdd.dd or ::IMASdd.dd — where it should accept ::IFEdd.AbstractIFEDD (or ::IMASdd.DD). Report it against the package that owns the method; see A sibling data dictionary.

World-age error right after @bake_dd — the baked type is not visible inside the same top-level expression. See Quick bake.
